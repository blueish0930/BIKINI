BIKINI - BUILDING FROM SOURCE
=============================

Upstream Blender build handbook:
https://developer.blender.org/docs/handbook/building_blender/

This file describes what the source tree contains, how this repository differs from upstream
Blender, which third-party libraries have to be fetched by hand, and how to reproduce the build
configuration that is verified on this machine.


1. WHAT THE SOURCE TREE CONTAINS
--------------------------------

After cloning, these directories are already part of the Git history:

source/                    The Blender application itself: window manager, editors, geometry
                           nodes, compositor, sequencer, Python API.

intern/                    Engines and bridges compiled with Blender, including Cycles, OpenVDB
                           and Mantaflow, plus BIKINI's LuxCore integration (intern/luxcore) and
                           the CGAL bridges (intern/cgal_bridge, intern/cgal_volume_bridge).

extern/                    Third-party sources committed to this repository, for example
                           Audaspace, Bullet, CGAL, Eigen, Jolt, OpenSubdiv and gtest. Each
                           library keeps its own license files.

scripts/                   Startup scripts, bundled add-ons, presets and templates.

release/                   Runtime data. Full third-party license texts live in release/license/.

locale/                    Interface translations.

assets/                    Brush and node assets.

build_files/               CMake configuration and the Windows build script (make.bat).

tests/, tools/             Tests and build helper tools.

patches/luxcore-bikini.patch
                           Local modification applied on top of LuxCore for_v2.11 (Cauchy B for
                           Rough Glass).

extern/luxcore and the platform libraries under lib/ are Git submodules. A plain "git clone"
only records their commit ids and leaves the directories empty, so they have to be initialized
separately; see section 2.


2. THIRD-PARTY LIBRARIES YOU HAVE TO FETCH YOURSELF
---------------------------------------------------

The submodules set "update = none" in .gitmodules, so "git clone --recurse-submodules" does not
check the platform libraries out either. Initialize them individually with the commands in
section 4.

2.1 Required to compile
.......................

lib/windows_x64            Blender's official Windows x64 precompiled libraries: Python, LLVM,
                           OpenEXR, USD, Embree, FFmpeg and others. Large; the files are stored
                           in Git LFS.
                           Fetch: https://projects.blender.org/blender/lib-windows_x64.git
                           Check out the commit that the parent repository records.

lib/windows_x64/spectra    Spectra, a header-only eigenvalue library (MPL-2.0). The geometry
                           nodes file linear_solver_math.cc includes include/Spectra/. This copy
                           is not in the official precompiled library repository.
                           Fetch: https://github.com/yixuan/spectra

Linux, macOS and Windows ARM64 use lib/linux_x64, lib/macos_arm64 and lib/windows_arm64
respectively; their URLs are listed in .gitmodules. Only the library of the current platform is
needed.

2.2 LuxCore engine
..................

WITH_LUXCORE is enabled by default. Once the sources and their dependencies are in place,
intern/luxcore compiles LuxCore, SLG and LuxRays into blender.exe. When sources or dependencies
are missing, the configuration step skips the kernel and the engine is only an empty shell.

extern/luxcore            LuxCore source, submodule branch for_v2.11, currently pinned at
                          125879e3c9a13b603e9d8ab4cdf4a6c61c0ecdc2. Apache-2.0, see
                          extern/luxcore/COPYING.txt after checkout.
                          Fetch: https://github.com/LuxCoreRender/LuxCore.git

extern/luxcore worktree   Apply patches/luxcore-bikini.patch. The patch ships with this
                          repository and is not part of the upstream commit.

extern/luxcore/out/       LuxCore's own dependencies: Boost 1.88.0, spdlog 1.17.0,
dependencies/full_deploy/ nlohmann_json 3.12.0 and robin-hood-hashing 3.11.5. Generated by Conan,
host                      not tracked in Git. Run "make.bat deps" inside extern/luxcore.

The marker file the kernel lookup uses is:

extern/luxcore/out/dependencies/full_deploy/host/boost/1.88.0/Release/x86_64/include/boost/version.hpp

extern/boost is a different Boost that Blender ships with and cannot replace that copy.

2.3 Needed only when the matching feature is enabled
....................................................

lib/windows_x64/optix      Cycles OptiX, and it has to contain include/optix.h. On non-Apple
                           platforms WITH_CYCLES_DEVICE_OPTIX=ON by default. When the header is
                           missing, the configuration disables OptiX and prints a warning.
                           Fetch: https://github.com/NVIDIA/optix-dev, or the complete OptiX SDK
                           from NVIDIA. The license is the LICENSE.txt inside the SDK.

lib/windows_x64/dlss       DLSS Ray Reconstruction, and it has to contain include/nvsdk_ngx.h.
                           "make.bat release" forces WITH_DLSS=ON, "make.bat full" leaves it off.
                           When the SDK is missing, the option is disabled.
                           Fetch: https://github.com/NVIDIA/DLSS (including its submodules).
                           The runtime libraries are expected under lib/Windows_x86_64/rel/ as
                           nvngx_dlss.dll, nvngx_dlssd.dll and nvngx_dlssg.dll. The license is
                           the LICENSE.txt inside the SDK.

These three directories (spectra, optix, dlss) are not part of Blender's official
lib-windows_x64 commit.


3. REQUIRED TOOLS
-----------------

Install these and put them on PATH:

- Visual Studio 2022 with the "Desktop development with C++" workload
- CMake
- Git, plus Git LFS ("git lfs install")
- Python 3, then "pip install conan" (only for LuxCore's "make.bat deps"; Blender itself uses
  the Python from lib/windows_x64)


4. BUILD STEPS (WINDOWS)
------------------------

The verified configuration is Visual Studio 2022 (vc17), x64, the "full" configuration and
Release. The build directory sits next to the source tree and is called
build_windows_Full_x64_vc17_Release, the executable is bin\Release\blender.exe.

Run these commands in an already opened "x64 Native Tools Command Prompt for VS 2022":

    git clone https://github.com/blueish0930/BIKINI.git
    cd BIKINI

    git submodule update --init extern/luxcore
    git -C extern/luxcore apply ../../patches/luxcore-bikini.patch

    git config --local submodule.lib/windows_x64.update checkout
    set GIT_LFS_SKIP_SMUDGE=1
    git submodule update --progress --init lib/windows_x64
    set GIT_LFS_SKIP_SMUDGE=
    git -C lib/windows_x64 lfs pull

    git clone --depth 1 https://github.com/yixuan/spectra.git lib\windows_x64\spectra
    git clone --depth 1 https://github.com/NVIDIA/optix-dev.git lib\windows_x64\optix
    git clone --recurse-submodules https://github.com/NVIDIA/DLSS.git lib\windows_x64\dlss

    cd extern\luxcore
    make.bat deps
    cd ..\..

    make.bat full 2022

When make.bat finds lib/windows_x64 still empty, it also offers to download it. The LFS objects
are large, so the first "lfs pull" takes a while.


5. OTHER BUILD ENTRY POINTS
---------------------------

make.bat 2022          Default configuration. LuxCore stays enabled, DLSS is off, OptiX is on.
make.bat full 2022     The same feature switches as the official full build; the output
                       directory carries "Full" in its name.
make.bat release 2022  Corresponds to the official release build and forces DLSS and OptiX on.
make.bat nobuild 2022  Only generate the Visual Studio projects.
make.bat help          All switches, including lite, ninja, debug, 2019 and 2026.


6. LINUX AND MACOS
------------------

Initialize the matching lib/<platform> submodule and extern/luxcore (the patch and "make deps"
are needed there as well), then run "make full" in the source root. The history of this
repository is an independent root commit with no common ancestor with upstream Blender, so do
not use "make update" to fast-forward onto the official main branch.
